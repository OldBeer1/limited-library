# Limited Library

主动限制收藏柜里的作品数量，同时完整保存看过、读过的作品记录的个人本地媒体管理应用。

**当前阶段：L0 设计已落盘，等待架构确认。当前仓库没有可运行的 Web App。** 任务书要求先确认设计，再实施 L1–L4；本文中的 npm 接口均为计划接口。

## 收藏柜与完整历史

- 收藏柜是有容量上限的精选保留区；看完仍可留在柜中，归档后释放位置。
- **已看／已读清单完整保存所有已完成作品，不限制记录数量。** 包含仍在收藏柜和已归档的记录；同一作品记录只显示一次。
- 六类分别提供已看电视剧、已看电影、已看动漫、已看纪录片、已看话剧、已读漫画入口。
- 已看记录可标记“收藏”，支持标题搜索、分类、评分、日期、备注与分页。收藏标记独立于柜内／归档位置；归档后也保留收藏标记。
- “补录已看／已读”直接进入历史区，不占柜子容量；想同时放进收藏柜时才检查容量、必要时进行替换。
- 正常添加到收藏柜的 planned、watching、completed、dropped 均占位；看完不自动归档。
- 归档保留资料、完成事实和收藏标记；永久删除移除这条记录，包括其已看清单记录，操作前须明确确认。
- 当前没有收到个人作品数据，仓库不包含虚构片单、爬取数据或真实私人记录。MVP 提供手动补录；批量导入另定格式与验收。

| 分类 | 键 | 默认收藏柜容量 | 完整历史入口 |
|---|---|---:|---|
| 电视剧 | tv | 10 | 已看电视剧 |
| 电影 | movie | 10 | 已看电影 |
| 动漫 | anime | 10 | 已看动漫 |
| 纪录片 | documentary | 6 | 已看纪录片 |
| 话剧 | theatre | 10 | 已看话剧 |
| 漫画 | comic | 5 | 已读漫画 |

默认总容量 51。归档与已看清单记录不额外增加收藏柜计数；已看清单中的柜内记录仍计入其分类容量。容量允许为 0，但必须先清空该分类的柜内作品。

## 拟采用技术

React + TypeScript + Vite 前端，Node.js + Fastify 本地后端，SQLite 与 better-sqlite3 驱动，npm workspaces。前端通过 API 读写，后端统一执行容量规则；localStorage 不作为主数据库。深色优先、低饱和、适配 375 / 768 / 1440px。

本机已检查到 Node v24.16.0、npm 11.13.0、Python 3.13.15、Git 2.54.0.windows.1。Node 24 为候选运行时，具体 npm 包版本须在 L1 安装、原生驱动验证后锁定。本阶段未安装项目依赖，没有 package.json / package-lock.json。

## 当前可运行的设计检查（PowerShell）

需要 Python 3.13（本机已存在）；不安装第三方包。

```powershell
Set-Location -LiteralPath 'C:\Software\Limited Library'
python .\scripts\check_design.py
```

该脚本只检查本阶段文档、SQL 草案，在内存或系统临时目录建立合成测试库，不读取真实个人数据库。检查通过不代表应用、HTTP API、better-sqlite3 或浏览器交互已实现。

## 计划中的数据位置与恢复

- 生产：`%LOCALAPPDATA%\LimitedLibrary\`，包含 `library.sqlite`、受控封面副本与最小日志。
- 开发：项目下 `.local-data\development\`，不会打开生产数据。
- 测试：由测试夹具建立的唯一临时目录；缺少测试路径即失败，不回落到生产路径。
- 数据目录、封面、备份、环境文件、本机发布报告均不提交 GitHub。GitHub 保存代码与设计，不同步个人媒体记录。
- MVP 首版提供**停服备份与独立目录恢复验证**。先关闭应用和所有数据库连接，再复制完整数据目录；不能在 WAL 运行中只复制主数据库文件。原库不覆盖；迁移前先备份。
- 封面仅手动导入副本，可为空；计划限制真实解码验证的 PNG / JPEG / WebP、5 MiB、像素总量。缺失显示占位，损坏数据库停止并报错，不自动清空。
